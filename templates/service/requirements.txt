# Runtime dependencies — everything the SERVED IMAGE needs, and nothing else.
#
# This file is what the Dockerfile installs. Every package below is imported,
# unguarded, by code that runs inside the image: the FastAPI app, common_utils,
# and the src/ modules the monitoring CronJobs invoke from the same image.
#
# Training-only packages live in requirements-train.txt; test and lint tooling
# lives in requirements-dev.txt. That split is not cosmetic — before it, the
# served image carried mlflow, optuna, pytest, pytest-cov, locust and httpx,
# none of which it imports, and with them 20 of the 24 fixable CRITICAL/HIGH
# advisories the dependency scan reported (all 7 CRITICAL among them).
# Measured: 150 resolved packages and 24 findings before, 35 and 4 after.
# See ADR-049. `scripts/check_dependency_partition.py` in the template repo
# fails if a training-only package reappears here.
#
# Pinning is `~=` (compatible release) by policy — D-05. `==` belongs in the
# lockfile (`make lock`), not here.
