# v0.30.1 — A fake key that GitHub kept reporting as real

Release date: 2026-09-28

Bump level: **PATCH**. Test-fixture content only. No scaffolded path,
contract or hook changes, so `MIGRATION.md` has no entry for it.

## Why this release exists

GitHub secret scanning opened a `google_api_key` alert in this repository and
again in a service generated from v0.30.0. The string was a deliberately fake
key. It is the sample in `test_context_files_hygiene.py` that proves the
template's own secret patterns still match, and `test_memory_redaction.py`
carried a second one. **Nothing leaked, and nothing needs rotating.** But every
repository that copies these files gets an alert that is always a false
positive, and that teaches its reader to dismiss alerts.

Both fixtures now build the string at runtime (`"AIza" + "Example" * 5`). That
exercises the same patterns and never matches as a literal. A new governance
test, `test_no_literal_key_shapes.py`, fails on any tracked file carrying a
literal Google-API-key shape (#241).

## Adopter impact

None. `copier update` to v0.30.1 replaces the two fixture lines. A service
generated from v0.30.0 that shows the alert can dismiss it as "used in tests".

## Known follow-ons

- **L4 remains unproven.** No cloud deployment is claimed.
- **The numpy 1.x boundary is still unmeasured**, and it blocks the `shap` and
  `pandas` majors.
- **Cursor lists every skill twice** (ADR-027 §10). This cannot be avoided,
  and the copies are kept identical.
