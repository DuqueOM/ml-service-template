# v0.30.2 — The fake private-key header beside the fake key

Release date: 2026-09-28

Bump level: **PATCH**. Test-fixture content only. No scaffolded path,
contract or hook changes, so `MIGRATION.md` has no entry for it.

## Why this release exists

v0.30.1 moved a deliberately fake Google API key in a test fixture to runtime,
because GitHub secret scanning reported the literal in every repository that
copied it. It left the fake PEM private-key header beside it. Every
`detect-private-key` hook refuses that header, and a downstream repository's
hook stopped a commit of a service generated from v0.30.1 on it.
`test_memory_redaction.py` carried a truncated PEM block, marked
`gitleaks:allow`.

Both fixtures now assemble the header at runtime, and the redactor still
receives the whole block. `test_no_literal_key_shapes.py` now also fails on a
literal PEM private-key header in any Python file (#243). **Nothing leaked, in
either release: these are fake values that prove the template's own detectors
work.** v0.30.1's fix should have covered every secret shape these fixtures
use, not only the one GitHub reported. This release is that correction.

## Adopter impact

None. `copier update` to v0.30.2 replaces the fixture lines.
