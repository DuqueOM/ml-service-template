# v0.32.0 — A patched pyarrow, and an EDA set that installs where the service runs

Release date: 2026-10-08

Bump level: **MINOR**. The generated `requirements.txt`, `pyproject.toml` and EDA requirement files change their
pins, which is changed scaffold output: not a PATCH (`docs/RELEASING.md` §1.1), and no §1.3 contract changes.
`MIGRATION.md` has no entry, because `copier update` brings the new pins and nothing else needs a manual action.

## Why this release exists

Two defects in what this template generates, both found by ml-platform, which consumes it (its QA-4 rounds
seventeen and eighteen):

- **CVE-2026-25087.** `pyarrow ~= 18.0.0` sat inside the vulnerable range, fixed in 23.0.1, in the service's
  `requirements.txt`, `pyproject.toml` and `eda/requirements.txt` — so in every generated image. It is
  `~= 25.0.1` now. Installed on the image's Python 3.13 beside the pinned `numpy ~= 1.26.0` and
  `pandas ~= 2.3.3`, a parquet round trip through pandas is exact.
- **The heavy EDA set could not install on the image's Python**, and could not be imported anywhere.
  ydata-profiling 4.12 depends on htmlmin, whose build imports `cgi` (removed in Python 3.13), and declares
  `<3.13`. It also imports `pkg_resources` without declaring setuptools, which a 3.12+ venv does not ship. The
  dependency scan resolves requirement files on the runner's Python 3.12 and never imports them, so neither
  showed. The set is now ydata-profiling `~= 4.17`, `matplotlib ~= 3.10` (every ydata-profiling from 4.13 caps
  it at 3.10.0) and `setuptools ~= 80.10`, and the earlier choice of matplotlib 3.11 over a newer profiler is
  reversed, with the evidence, in Dependabot's ignore entries.

A new lane, `eda-heavy-smoke.yml`, installs the heavy set on the Python the Dockerfile names and builds a
profiling report: weekly, and on any change to the EDA requirements. The previous set fails it with
`ResolutionImpossible`.

Also in this release: the README follows a standard shared with ml-platform, and its check reads Markdown as
GitHub renders it (#265, #266, #267).

## Adopter impact

- The next `copier update` moves pyarrow to 25 in three files, and the heavy EDA set to the versions above. If you
  had pinned matplotlib 3.11 for other reasons, the heavy set cannot be installed beside it until ydata-profiling
  lifts its cap.
- If your security baseline accepted CVE-2026-25087 for pyarrow 18, the entry can be removed after the update.

## Known follow-ons

- **L4 remains unproven.** No cloud deployment is claimed.
- **The numpy 1.x boundary is still unmeasured**, and it blocks the `shap` and `pandas` majors.
- **matplotlib is held at 3.10.0** by ydata-profiling's cap; Dependabot's ignore entry says when to lift it.
- **Two service skill names are generic enough to collide with an adopter's own** (`doc-coherence`,
  `enterprise-audit`). Reported downstream; a rename is a template decision not yet taken.
