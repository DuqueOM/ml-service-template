# v0.29.0 — Four layers that each chose a name, and the alarms that only fired one way

Release date: 2026-09-21

Bump level: **`v0.x.0`, MAJOR-class** (`docs/RELEASING.md` §2.1). Cloud identity
names, the runtime secret addressing scheme and the values a scheduled workflow
reads all change, so this carries the full MAJOR paperwork: a
`### Breaking for adopters` block in `CHANGELOG.md` and a matching `from → to`
section in `MIGRATION.md`. `v1.0.0` stays reserved for real cloud E2E evidence.

## Why this release exists

v0.28.0 said *"the template-side blockers to attempting L4 are gone"*. They
were not.

**No staging or production pod could authenticate a single request, on either
cloud, and every deploy went green.** Nothing was wrong in any one file. Four
layers each chose a name and no two agreed:

| Layer | Named | Actually deployed |
| --- | --- | --- |
| GCP Workload Identity member | `ml-services/<project>-sa` | `<service>-<env>/<service>-sa` |
| GKE ServiceAccount annotation | `<service>-sa@…` | Terraform creates `<project>-runtime-<env>@…` |
| AWS IRSA trust `sub` | `ml-services:<service>` | `<service>-<env>:<service>-sa` |
| EKS ServiceAccount annotation | `<service>-irsa-role` | Terraform creates `<project>-<service>-irsa-<env>` |
| Secret requested | `<slug>-API_KEY` | `<project>-<service>-api_key` |
| Environment variable read | `ENV` | overlays set `ENVIRONMENT` |
| Cloud SDK in the served image | required by the loader | installed by nothing |

A pod bound to nothing has no cloud identity, so it could not download its
model either. And the AWS OIDC trust allowed `environment:<environment>` while
a job declaring `environment: aws-production` presents
`environment:aws-production` — so **no deploy job could assume its role**, on
top of everything else.

**The post-deploy smoke test could see none of it, and could not have run.** It
probed only `/ready`, which touches no secret. Its pod was tag-pinned, which
Kyverno rejects in staging and production; it lacked the PSS `restricted`
context prod enforces; and NetworkPolicy default-deny gave it no egress and the
predictor no ingress rule for it. kind enforces none of those three, which is
why the golden path stayed green throughout.

See [ADR-051](../docs/decisions/ADR-051-runtime-identity-and-secret-addressing.md).

## What the smoke test proves now

It calls an auth-protected endpoint with a **deliberately wrong, per-run** key:

```text
auth enabled  -> 401   the secret resolved and the comparison ran   (pass)
                 503   the secret is not resolvable                 (fail)
auth disabled -> 200   the endpoint is reachable                    (pass)
```

CI never holds the real key, so the deploy identity needs no secret access
(D-31). The pod is digest-pinned, runs `restricted`, and is admitted by a
NetworkPolicy keyed on one label that only that step sets.

## The alarms fired one way only

`golden-path.yml` opened issue #177 when L3 went red on 2026-09-12 and
**nothing ever closed it**. The lane went green on its next two runs while the
issue kept telling every reader that L3 was failing; three days later it was
the repository's only open signal and it was wrong. The closed-loop lane had
the mirror defect: no notifier at all, for the one lane that proves D-21/D-22.

Both lanes now raise **and retract**, under separate labels, asserted by
`test_lane_signals_both_ways.py`. An alarm that cannot be retracted is
indistinguishable from a stale one.

## Dependency review moved from per-PR to per-boundary

Twenty-nine Dependabot PRs arrived across three waves in one day. Reviewing
each one came down to reading a version number, while the decisions that
mattered were made once, in configuration:

- **Four were red by construction.** The `github-actions` entry used a singular
  `directory:` per tree, so every action bump arrived as half a change and the
  drift gate rejected it. The file's own comment claimed scanning both
  directories "lets one PR satisfy it" — the intent was recorded and the
  implementation was two entries.
- **Two were policy.** `shap >= 0.50` requires `numpy >= 2`, which D-05
  excludes; `pandas 3` cannot coexist with `ydata-profiling` in the EDA lane.
  Both are now `ignore` entries carrying the measurement that justifies them.
- **The rest are what CI is for.** Since [ADR-052](../docs/decisions/ADR-052-automated-dependency-merges.md),
  patch, minor and digest updates merge themselves when every required check
  passes; a major waits for a person. Six merged unattended on the first day,
  including a `pandas` minor that moved the pin in both files at once — the
  shape that used to arrive split and red.

Majors were batched by hand and measured in a virtualenv built from the new
pins: `optuna 5`, `mypy 2.3.1` (with both pre-commit hook revs moved to match),
`pytest 9.1.1`, `github-script v9`. The payload suite reports the same
689 passed / 19 skipped before and after.

## The gate that caught me

pandas 3 was in that batch. I resolved five requirement groups locally; the
heavy EDA lane was not one of them. The `Self-audit` lane resolves **every**
requirements file to exact versions and failed the PR:

```text
The user requested pandas~=3.0.6
ydata-profiling 4.18.4 depends on pandas!=1.4.0, <3.0 and >1.5
ERROR: ResolutionImpossible
```

D-05 is now an assertion rather than a setting too. `check_pin_shape.py`
(gate 21) rejects a widened range, an `==` declaration and a bare name across
74 pins in 11 files — added because Dependabot opened
`dependabot/pip/templates/service/pytest-gte-8.3-and-lt-9.2`, the shape it
proposes when it *widens* a constraint. A widened pin reads as pinned, passes
every other dependency gate, and still hands the next major to whoever runs
`pip install` first.

## Known follow-ons

- **L4 remains unproven.** No cloud deployment is claimed.
- **The drift CronJob has no NetworkPolicy path** under default-deny (#182).
- **No Terraform-backed GitHub Actions identity** for the nightly plan, drift
  and retrain; this release fixes their channel, scope and naming only (#183).
- **The numpy 1.x boundary is still unmeasured**, and now blocks `shap` and
  `pandas` majors as well.
- **The first auto-merge has happened; the first auto-merged regression has
  not.** ADR-052 is explicit that the quality of the automation is now the
  quality of the gates.
