# v0.27.0 — Nine controls that agreed with a broken codebase

Release date: 2026-09-11

Bump level: **MINOR number, MAJOR-class obligations** (`docs/RELEASING.md` §2.1).
Several changes rename scaffolded files and a contract test, so the full
`### Breaking for adopters` paperwork and a matching `MIGRATION.md` section ship
with this release.

## What was actually wrong

Eight defects, and they are the same defect. Every one of them sat behind a
control that reported success:

| What was broken | What said it was fine |
| --- | --- |
| `requirements.txt` and `eda/requirements.txt` were `ResolutionImpossible` together, and the tutorial installs both | pip, because two install commands never conflict — the second silently upgraded the first |
| the generated service's entire CLI raised `ImportError` on import | nothing; `evaluation.py` and `evaluation/` both existed and Python just picks the package |
| `dvc repro` had never completed — three of four stages pointed at files that do not exist | nothing read `dvc.yaml` |
| the drift CronJob ran with input validation silently off | a warning whose own text says that branch "exists only for template-level tests" |
| the same broken invocation lived in 13 places | a guard that read the Makefile and nothing else |
| MLflow was installed in every inference pod carrying 20 of 24 CRITICAL/HIGH advisories | ADR-047, correctly noting `app/` does not import it — and drawing the wrong conclusion |
| `mlflow.tracking_uri` was parsed, validated and read by nothing | pydantic, which validates values nobody consumes |
| MLflow 3.x breaks this template's model logging | ADR-047's own round-trip test, run on a pipeline that lacked the failing component |

The last two are the shape of the whole release. **A measurement taken on a
proxy is not a weaker version of the real one; it is a different one, and the
difference is where the failure lives.**

## The fix

Three ADRs, three new gates, and gates 15 → 18:

- **[ADR-048](../docs/decisions/ADR-048-requirements-co-installation-groups.md)** —
  requirements files installed into one environment must agree on pins,
  *identically*, not merely compatibly. `check_dependency_pin_coherence.py`.
- **[ADR-049](../docs/decisions/ADR-049-runtime-training-dependency-partition.md)** —
  the served image installs only what it runs: **151 packages → 35**,
  **24 fixable CRITICAL/HIGH → 4, and 7 CRITICAL → 0**.
  `check_dependency_partition.py`.
- **[ADR-050](../docs/decisions/ADR-050-configuration-must-be-read.md)** —
  declared config must be read, or say it is not. `check_config_is_read.py`.
- **[ADR-047 §Amendment](../docs/decisions/ADR-047-mlflow-3-migration.md)** —
  MLflow 3.16 taken, and the original ADR's conclusion corrected.

The MLflow baseline is **closed**: 20 accepted findings removed, `27 → 7`, the
2026-12-08 forcing function discharged three months early.

## Breaking for adopters

Every row has a manual action in [`MIGRATION.md`](../MIGRATION.md).

| Change | Manual action |
| --- | --- |
| **MLflow pinned `~= 3.16.0`; local backend is SQLite** | Run `mlflow migrate-filestore --backend-store-uri sqlite:///mlflow.db --file-store ./mlruns` before your first training run. MLflow 3.x refuses `file:./mlruns` outright, and it fails *after* training has spent its Optuna budget. |
| **`mlflow.tracking_uri` now takes effect** | Read your `configs/config.yaml` before the next run. `MLFLOW_TRACKING_URI` still wins. The `staging`/`prod` profiles naming an in-cluster server were decorative for training and are live now, so that service must exist. |
| **`requirements.txt` is the serving set only** | `make install` no longer prepares a training environment — use `make install-train`, or `make install-dev` for tests. `make lock` emits two lockfiles. |
| **`src/<slug>/evaluation.py` → `evaluation/metrics.py`** | None unless you imported the module path directly; `from .evaluation import ModelEvaluator` works and did not before. |
| **`dvc.yaml` is two stages, through `cli.py`** | If you implemented `validate_data.py`/`evaluate.py` yourself, re-add your stages. The two removed ones pointed at files that never existed. |
| **`tests/test_makefile_entrypoints.py` → `test_python_entrypoint_invocations.py`** | Update any reference. It now reads every shipped surface, not just the Makefile: 39 invocations checked, up from 3. |
| **Three `:latest` compose images pinned** | None unless you depended on them floating. |

## Known follow-ons (scoped, not regressions)

- **24 of 51 declared config fields are read by nothing** — including
  `data.categorical_features`, which the adopter is told to fill in and which
  `model.py` overrides with a module constant, and
  `quality_gates.promotion_threshold`, a documented promotion gate with no
  enforcement. Counted and ratcheted by `check_config_is_read.py`; each carries a
  `⚠ NOT YET WIRED` banner in `config.yaml`. Wiring them is behaviour change with
  its own decisions and belongs in its own releases. **The fields stay** — the
  pipeline *should* honour them, and deleting the declaration would remove the
  promise instead of keeping it.
- **The numpy 1.x boundary's rationale is unmeasured.** *"numpy 2.x silently
  corrupts joblib models"* is a 2024-era claim defended by a comment and now by a
  gate. Whether it still holds for current scikit-learn and joblib needs a
  measured round-trip across the boundary, an ADR and a release of its own.
- **L4 remains unproven.** No cloud deployment is claimed by this release.
  `v1.0.0` is still reserved for real GKE + EKS evidence, unchanged.
